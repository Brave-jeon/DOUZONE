# SalesPilot 무료 공유 로그인

## 구성과 현재 상태
- GitHub 저장소 코드를 Render Free 실행 서버에 연결합니다. 유료 디스크는 사용하지 않습니다.
- 계정과 문서 데이터는 암호화된 상태로 Supabase Free 데이터베이스에 보관합니다. Render 임시 파일은 원본 저장소가 아닙니다.
- 기존 이메일·비밀번호 검증값을 이전하므로 같은 계정을 사용할 수 있습니다. PC 원본 DB와 보안 키는 GitHub에 올리지 않습니다.
- 배포 코드와 임시 데이터 검증 준비 단계입니다. 실제 무료 서비스 연결·계정 이전·인터넷 로그인 검증이 완료돼야 사용 가능합니다.

## 무료 서비스 연결 순서
1. Supabase에 로그인해 **Free** 조직·프로젝트를 선택하거나 만듭니다. 유료 업그레이드는 선택하지 않습니다.
2. 프로젝트 SQL 편집기에서 `supabase-setup.sql` 전체를 실행합니다. 기존 암호화 데이터 행을 초기화하지 않으며, 서버용 권한에만 접근을 허용합니다.
3. Render에서 새 Blueprint를 만들고 `Brave-jeon/DOUZONE` 저장소와 `shared-login-free-20261112` 브랜치를 선택합니다.
4. 실행 요금이 **Free**, 유료 디스크가 없는지 확인합니다. 유료 비용이 표시되면 생성하지 않습니다.
5. Render 비밀 환경변수에 Supabase 프로젝트 URL과 서버용 키를 직접 입력합니다. `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`입니다. 공개용 키를 대신 사용하지 마세요.
6. `MIGRATION_KEY`에는 별도 `migration-key.txt`, `STORE_ENCRYPTION_KEY`에는 별도 `database-encryption-key.txt` 내용을 직접 입력합니다. 키는 채팅·GitHub 파일에 넣지 않습니다. 두 키는 서로 달라야 합니다.
7. 무료 서버를 배포하고 제공되는 HTTPS 주소를 확인합니다. 자동 배포는 꺼져 있습니다.
8. `계정이전_실행.cmd`를 실행해 공유 서버 주소를 입력하고 전송에 동의합니다. 원본 DB는 읽기 전용이며, 기존 데이터가 있는 대상에는 덮어쓰지 않습니다. 기존 세션과 로컬 원본 첨부 파일은 자동 이전하지 않습니다.
9. 같은 이메일·비밀번호로 로그인해 확인한 뒤 `MIGRATION_KEY`를 환경변수에서 제거합니다. 암호화 키는 삭제하거나 변경하면 기존 데이터를 읽을 수 없으므로 안전하게 보관합니다.
10. 검증된 HTTPS 주소를 `app/shared-config.js`에 입력하고 GitHub Pages에 연결합니다. PC에서도 이 공통 주소로 접속합니다. 서로 다른 주소의 쿠키를 공유하지 않고, 동일한 앱·회원 데이터를 사용합니다.

## 데이터 보존과 보안
- AES-256-GCM 암호화, 서버용 데이터베이스 권한, 버전 확인을 통한 원자적 저장을 사용합니다.
- 저장 확인 전에는 성공 응답과 로그인 쿠키를 보내지 않습니다. 실패 응답은 저장 확정을 뜻하지 않으며 다시 확인해야 합니다.
- 동시 저장 충돌은 최신 데이터로 복구 후 재시도합니다. 무료 서버가 다시 시작되면 확정된 데이터를 복원합니다.
- 임시 데이터를 사용해 재시작·동시 저장·실패 응답을 검증했습니다. 실제 Supabase SQL 권한과 실제 인터넷 연결 검증은 배포 후 필요합니다.

## 무료 한도
- Render Free는 미사용 시 휴면하며, 재접속 시 시작이 늦어질 수 있습니다. 작업공간의 무료 실행 시간은 월 750시간입니다.
- Supabase Free 데이터베이스는 프로젝트당 500MB입니다. 무료 프로젝트는 1주일 미사용 시 일시 중지될 수 있습니다.
- 사용량·트래픽·저장 용량 한도가 있으며 업무용 가용성을 보장하지 않습니다. 한도 초과 시 유료 전환 대신 작업을 중단하고 확인하세요.
